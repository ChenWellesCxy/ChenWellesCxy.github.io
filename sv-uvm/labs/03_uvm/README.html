Lab 03：UVM 简化存储器总线

项目文档快照 · 2026-10-21 · 查看原文 ↗

本实验从 transaction 到 test 组成一个最小 UVM 环境：sequence/sequencer、driver、monitor、scoreboard、agent、env 与 test。它用来练习 UVM 数据流，协议刻意简化，不代表 DRAM/JEDEC 协议。

总线约定

  • 8 位 byte 地址；每个 word 4 bytes；只接受 addr[1:0] == 0，索引是 addr >> 2。
  • DUT 有 64 个 word，对应 byte 地址 0x00 到 0xFC。
  • 最多一笔未完成事务。ready = req && rst_n，因此无等待周期。
  • driver 在下降沿改变请求；driver 与 monitor 在上升沿观察握手；读数据组合输出。
  • 仿真时钟周期 10 ns。复位不清空存储内容。

文件

  • mem_if.sv：教学总线 interface。
  • mem_dut.sv：教学存储器 DUT；+INJECT_ERROR 会让读数据 bit 0 翻转。
  • mem_pkg.sv：UVM transaction、directed + constrained-random sequence、driver、monitor、scoreboard、agent、env、test。
  • tb.sv：时钟、复位、virtual interface 配置、run_test 和全局 watchdog。
  • run_questa.sh：使用既有 Questa 与 UVM 源码编译和运行。

运行

需要已安装且可用的 Questa，并准备与它兼容的 Accellera UVM 源码目录。UVM_HOME 指向包含 uvm_pkg.sv 和 uvm_macros.svh 的 src 目录，QUESTA_HOME 指向 Questa 安装根目录。例如在 WSL bash 中：

export QUESTA_HOME=/path/to/questa
export UVM_HOME=/path/to/uvm/src
cd "/path/to/SV&UVM Learning/labs/03_uvm"
bash run_questa.sh

正常流必须精确完成 9 次读检查与 9 次写，并以零 UVM_ERROR/FATAL 结束。故障注入应使 9 次读都产生 mismatch，脚本验证 [EXPECTED_FAULT] 标记和 UVM_ERROR 数量后以退出码 1 结束，表示 DUT 故意注入的错误已被 checker 捕获：

bash run_questa.sh fault

故障模式预期在 UVM log 中出现 9 条 [SB_MISMATCH]；这是故意注入的错误。全局 watchdog 防止 sequence 或握手停滞，test 会检查读写与比较次数。仿真 transcript 保存在 work/questa_normal.log 或 work/questa_fault.log。脚本使用 UVM 标准类与 Questa 常规命令，尚未在商业仿真器上验证，运行结果须以你的 Questa/UVM 安装为准。

学习顺序

  1. 从 mem_sequence.body() 找出两笔 directed 操作，再定位后续随机读写对。
  2. 沿 start_item/finish_item、seq_item_port、接口握手追踪一笔操作。
  3. 对照 monitor 的 analysis port 连接，追到 scoreboard 的 write()。
  4. 修改 DUT 故障注入方式或地址，观察 scoreboard 如何检测错误。
  5. 将 repeat (8) 改为更多轮次，记录 transaction 数和 scoreboard 检查数。

验收时能讲清：sequence 产生什么、driver 如何握手、monitor 如何重建实际事务、scoreboard 如何建立期望，以及错误注入如何证明 checker 会失败。

Verilator + Accellera UVM 运行入口

当前 WSL 已实测 Verilator 5.052 与 Accellera UVM 2020.3.1。优先使用：

cd "/mnt/d/cxy/SV&UVM Learning/labs/03_uvm"
bash run_verilator.sh normal
bash run_verilator.sh fault

脚本会自动使用 UVM_HOME，并把生成目录放在无空格的 /tmp 路径。正常用例要求 UVM_ERROR=0/UVM_FATAL=0；fault 用例要求 scoreboard 捕获 9 次 mismatch。运行后可用 gtkwave build_wave.vcd 查看真实 VCD 波形。
