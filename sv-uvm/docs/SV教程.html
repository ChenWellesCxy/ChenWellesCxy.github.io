从 DRAM Pattern 到 SystemVerilog 验证

项目文档快照 · 2026-10-21 · 查看原文 ↗

这是入门篇。系统深入阅读请接 官方文档学习导航、SV基础详解 和 SV验证详解，其中增加了详细语义、易错点和练习答案线索。

你并非没有验证经验；当前缺少的是把经验写成数字验证环境的语言和组织能力。本教程先唤醒 Verilog 基础，再解释 SV 的抽象方式，最后走到 CoverageModel 的独立实现。没有时间安排，按理解程度阅读即可。

读法：先预测现象，再运行，再解释，再改一个条件。 复制代码能运行只是第一步。能解释为什么这样采样、能主动制造失败、能判断失败来自设计还是检查器，才形成验证能力。

本文中实验01、02、04可在当前WSL的 Icarus上运行；标注“教学片段”的 class、约束、SVA、covergroup代码需支持对应特性的仿真器，不能直接当作当前Icarus的完整工程。运行记录单独保存，不把工具限制当成语言限制。

1. 先把工作经验转换成验证职责

原来熟悉的事情 数字验证对应职责 需要补的代码能力
选择命令与先后顺序 stimulus / sequence task、transaction、约束与场景组合
按时序发送Pattern driver 时钟同步、握手、timeout、reset处理
查看CA/DQ及内部波形 monitor 从真实引脚恢复事务，不依赖刺激脚本自报
判断操作是否符合预期 checker / scoreboard 参考模型、自动比较、诊断信息
关心是否测到关键条件 functional coverage bins、cross、采样条件及覆盖闭环
分析边界或非法命令 assertions / negative tests 时间关系、前提条件、预期失败

FineSim还关心连续时间的电压、电流和模拟电路行为；本教程的数字模型不会复现这些。可迁移的是协议、场景、边界、检查与debug经验。也不要把平时使用的“Pattern Sequence”直接等同于 uvm_sequence 类，它们可能职责相似，但实现和调度机制不同。

2. 环境与第一次运行

在 Ubuntu 终端中执行：

cd '/mnt/d/cxy/SV&UVM Learning'
bash scripts/run_labs.sh

路径有空格和 &，因此必须加引号。脚本使用 iverilog -g2012 编译、vvp 执行，保留正常日志、故障日志和VCD。它还会检查故障用例确实失败，避免“检查器失效但回归全绿”。

各实验的 labs/<实验>/build/wave.vcd 可以用已安装的 GTKWave 或其他 VCD 查看器打开。没有查看器也可直接打开 docs/waves/*.svg，这些图从同一次实验的真实 VCD 生成；只展示部分信号，完整信息在 VCD 中。

实验是教学协议，不是DRAM仿真器。 不需要生产TB、私有DUT或公司环境即可学习。

3. Verilog复习：电路同时工作，过程里的语句依次执行

module 描述结构；多个 always 与 initial 并发运行。同一个 begin/end 内按语句顺序执行，但非阻塞赋值把更新推迟到NBA区域。仿真时间不等于代码行数：没有 #、@、wait 等时间控制的循环可能在同一仿真时刻完成，甚至零时间死循环。

always @(posedge clk) begin
  q <= d;
  q_delay <= q;
end

两个右值在过程执行时求值；q_delay 得到更新前的 q，形成两级流水。若把两句都换成阻塞赋值 =，第二句在同一过程中看到刚更新的 q，行为改变。

  • 时序RTL通常使用 always_ff + <=。
  • 组合RTL通常使用 always_comb + =，给每条输出路径赋值，避免意外锁存器。
  • TB里的局部计算、计数、对象赋值常用 =。不要把“所有always都用非阻塞”当规则。
  • initial 常用于TB初始化；always 会反复执行。DUT和TB共享时钟时，同一上升沿直接读写可能竞争。

实验01：亲眼看到NBA更新

源码：labs/01_scheduling/tb.sv。先预测15ns、25ns的 q 与 q_delay，再运行。

10ns下降沿把 d=1；15ns上升沿后 q=1,q_delay=0。20ns把 d=0；25ns后 q=0,q_delay=1。上升沿的 $display 在NBA更新前打印旧值；TB里的 #1 检查在1ns后读取更新值。这里 #1 只是小实验的观察窗口，不是生产环境通用防竞争方案。

动手： 先在纸上预测把第二句改为 q_delay <= d 会怎样，再修改并看原checker是否失败。恢复后解释“时钟沿之前稳定输入”与“时钟沿之后更新输出”的区别。

验收： 不运行也能算出两拍结果；知道VCD同一物理时刻可能包含多个delta更新，普通波形图不一定展示调度区域细节。

4. 类型：logic、bit、枚举与结构体

logic 是四态变量类型，可表示0/1/X/Z；bit 只有0/1，转换时可能丢掉未知信息。wire 表达网络连接，logic 不是“任何位置都能替代wire”的规则，尤其多驱动和双向总线需要考虑网络解析。

logic [7:0] dq;          // 8位四态数据
bit valid;              // 已经明确的内部布尔状态
logic [7:0] memory[16];  // 16个8位元素，数组维度在名字后
logic [1:0][3:0] ca;     // 共8位packed量，能按子字段选择
typedef enum logic [1:0] {NOP, ACT, RD, PRE} cmd_t;
typedef struct packed {
  logic valid;
  cmd_t cmd;
  logic bank;
} event_bits_t;

packed表示能连续看作位向量；unpacked数组表示一组元素。包含 realtime 等非整型字段的事件结构不能随意改成packed。数组越界、位宽截断和signed/unsigned混算，常比漏写关键字更难发现。

== 遇到X/Z可能得到X；=== 总产生明确的0或1。在自检数据比较中常用 !==，让未知值也触发不匹配；但若把观察值提前存进 bit，X可能已经丢了。$isunknown() 可用于检测未知，需确认仿真器四态行为。Verilator主要是二态工具，不能用它的结果代替四态X传播实验。官方说明

动手： 把一组命令的 valid/cmd/bank/timestamp 写为struct；解释 logic [1:0][3:0] a 与 logic [3:0] a[2] 的整体赋值差别。

5. task、function、package：把Pattern变成可复用操作

function用于不消耗仿真时间的计算，task可以包含等待。function不能直接调用会阻塞的task或放入时间控制。task也不是必须耗时，只是允许耗时。automatic 让每次调用拥有独立局部存储，便于重入和并发；module内子程序默认静态的细节值得注意，class方法局部变量默认automatic。

function automatic logic [7:0] merge_bits(
  input logic [7:0] old_value, new_value, mask);
  return (old_value & ~mask) | (new_value & mask);
endfunction

task automatic issue_write(input logic [3:0] a, input logic [7:0] data);
  @(negedge clk);
  req=1; wr=1; addr=a; wdata=data;
  @(posedge clk);             // 等待接口采样
  @(negedge clk); req=0;
endtask

package 放共享类型和函数。使用前先编译包，再 import pkg_name::*;；include 是文本包含，不会创建命名空间，重复include可能重复定义。教程参考项目正是“公共package + 采样interface + coverage module包含多个svh”的组织方式。

动手： 用 merge_bits(8'hA5,8'h3C,8'h0F) 手算结果，写3组自检；再把实验02的transfer拆成write/read两个包装task，而底层仍复用transfer。

6. 自检TB：先有判定，再谈随机

实验02是16个8位word的教学存储器，地址是word索引0..15。ready = rst_n && req；每个 req && ready 的上升沿完成一笔事务，写数据在NBA更新，读数据由当前地址组合输出。没有等待周期或多个未完成请求。

实验03另用8位byte地址、4字节word的教学总线，两者是不同实验，不能直接混用地址索引。

先看信号关系：下降沿驱动请求，下一上升沿采样；driver保留请求直到下一下降沿撤销。ready 跟着req并不说明下降沿已经完成传输，协议规定的完成点仍是上升沿。

源码 labs/02_memory/tb.sv 包含四个职责：

  1. DUT保存数据；复位清零。
  2. transfer task驱动请求；只管接口动作。
  3. passive monitor在每次真实握手时观察读写、地址和数据。
  4. scoreboard根据观察到的写维护模型，再检查观察到的读。

这里monitor和scoreboard放在同一个过程，便于初学；之后用class和UVM把职责拆开。参考模型不读取DUT内部 mem 作为期望值，否则DUT写错时模型也跟着错，就失去独立检查作用。

正常场景含：复位后读零、遍历全部地址写读、20组随机地址写读、再次复位后读零。日志统计36次写、38次读，且三个seed运行。+INJECT_ERROR让DUT写入时翻转最低位，checker应报告地址、期望值和实测值并非零退出。

动手： 增加“同一地址连续写两次再读”；增加全0/全1数据；先手写预期，再加场景。若扩展事务数量，同步调整最终检查计数。不要删掉报错让它变绿。

验收： 能说明checker何时更新模型；能证明它会发现错误；能解释为什么只看 $display("PASS") 不足以证明测试有效。

7. 数组、队列、关联数组：参考模型用什么存储

固定数组适合小型已知深度memory；动态数组用 new[n] 动态分配；queue支持 push_back/pop_front，适合FIFO参考模型；关联数组适合只记录少量访问的大地址空间。

// 教学片段：依工具支持编译
byte unsigned expected_fifo[$];
logic [31:0] expected_mem[longint unsigned];
expected_fifo.push_back(8'h5A);
if (expected_fifo.size()==0) $fatal(1,"unexpected output");
expected_byte = expected_fifo.pop_front();
if (expected_mem.exists(address)) compare(actual,expected_mem[address]);

检查队列前判空，防止“取不到数据却按默认值继续比对”。关联数组中“没有这个地址”不同于“这个地址的预期数据是0”。遇到读未写地址，要先依据DUT规格决定行为，不能随便填一个期望值。

动手： 为FIFO列出空、满、同时push/pop、指针回绕、复位时有待比较数据这些场景。暂时不用UVM，先画预期队列长度变化。

8. interface与clocking block：让信号访问有共同约定

interface把一组信号和相关访问规则放在一起；modport描述角色可见方向。class不能像module一样连实体端口，可以通过 virtual interface 句柄访问已实例化的interface。virtual interface不是创建一套新硬件，而是引用顶层已有的实例。

// 教学片段
interface bus_if(input logic clk);
  logic req, ready, write;
  logic [7:0] data;
  clocking cb @(posedge clk);
    default input #1step output #0;
    input ready;
    output req,write,data;
  endclocking
  modport DRIVER(clocking cb);
endinterface

input #1step取时钟事件前的样本，防止和同沿DUT更新混读；output #0的驱动遵循clocking block调度，不要和普通过程的 #0 等同。具体skew必须符合接口协议，并不是抄上面几行就能解决任何race。教学实验先用下降沿驱动、上升沿采样，把边界讲清楚，再引入clocking block。

验收： 能指出信号由谁驱动、何时稳定、何时采样。读源码时主动找同一信号的多个写入者。

9. class：事务是“对象”，变量里放的是“句柄”

struct适合值式数据记录；class适合带方法、继承和随机化的事务对象。mem_item a;只声明句柄，a = new();才创建对象。

// 教学片段
class mem_item;
  rand bit write;
  rand bit [3:0] addr;
  rand bit [7:0] data;
  function void print();
    $display("write=%b addr=%h data=%h",write,addr,data);
  endfunction
endclass
mem_item a,b;
a=new(); a.addr=3;
b=a; b.addr=5; // a.addr也变成5，因为是同一个对象

SV的 new a 是浅拷贝，嵌套class成员仍可能共用句柄；UVM的copy/clone通过字段或do_copy实现复制，也必须核实嵌套对象策略。monitor把对象发布给多个消费者之后，不应随意再改它。每笔创建新对象或显式复制，是常用约定。

继承允许在基础item上增加字段；virtual方法允许通过基类句柄调用派生类实现；$cast做运行时类型检查，失败要处理。这是理解UVM factory override的前提。

动手： 写一个普通class，比较 b=a 与创建第二个对象后逐字段复制。再加一个嵌套对象，观察浅拷贝为什么还会共享部分状态。

10. 约束随机：表达合法空间，再观察覆盖

// 教学片段
class request;
  rand bit [7:0] addr;
  rand bit write;
  constraint legal_addr { addr inside {[8'h00:8'h3f]}; addr[1:0]==0; }
  constraint mix { write dist {1:=3, 0:=1}; }
endclass
request r;
r=new();
if (!r.randomize()) $fatal(1,"randomization failed");

rand不会自动执行；每次 randomize() 才求解。dist表达权重，并不保证每四笔恰好三写一读；短仿真尤其会偏离比例。inside表达集合；inline constraint增加本次约束，与类约束同时成立。冲突时返回失败，必须检查返回值，不能忽略后继续使用旧字段。

若要覆盖ACT→RD边界，不应该只随机等待0..1000拍并期待恰好撞到关键点；先有定向的门限-1、门限、门限+1，再随机探索组合。合法约束和故障注入要分开定义，避免约束让非法用例永远产生不了。

保存seed、工具版本、用例和代码提交号。相同seed不保证不同工具或不同版本生成完全一致的序列。实验02是 $urandom 的程序式随机，不是class约束求解，两者不要混淆。

11. 并发、mailbox与event：通知不等于数据队列

fork...join等所有子进程；join_any等任一个结束但其他进程继续存在；join_none启动后不等待，子进程开始时机受父进程挂起/结束影响。超时线程如果不清理，可能在后续场景中误报。

mailbox是进程间传递数据的通道，get可以等数据；event只通知某件事发生。先触发再去 @(e) 等待，可能错过事件；wait(e.triggered)可处理同一time slot内已触发的情形，但event仍不是持久队列。

参考项目用共享struct字段保存事件数据，再触发命名event。状态更新过程和covergroup被同一个event唤醒时，不能简单假定“代码写在前面就先更新”。独立实现时最好明确“构造完整样本→更新模型→显式采样”的顺序，或使用不可变样本与清楚的阶段边界。

动手： 描述两个消费者需要保存未来再比较的事务时，为什么不能只依靠一个共享 last_event。给出queue/mailbox或对象复制方案。

12. 断言：定义“哪里不允许错”

立即断言在过程执行到该语句时检查条件；并发断言在采样事件上检查跨时间关系。

// 教学片段：并发SVA需支持它的仿真器
assert property (@(posedge clk) disable iff (!rst_n)
  (req && !ready) |=> req && $stable({addr,write,wdata}));

这条教学协议要求：本拍请求没被接收，下拍仍保持请求及负载。|=>从下一采样周期检查后件；|->从本次匹配结束周期检查。$past读取前一采样历史；复位后首次采样的历史有效性要单独考虑。disable iff用于禁用断言，语义不是coverpoint的 iff。

如果永远没有出现 req && !ready，断言可能真空通过，所以还需证明前件被激发。实验02没有等待周期，这条断言在它上面没有足够锻炼；必须扩展ready延迟再测试。断言检查局部规则，scoreboard检查端到端数据，二者互补。

动手： 为“RD之前同bank必须有ACT”写立即检查；为等待期间请求稳定设计一个会失败的波形。解释为什么一条断言0次失败并不一定意味着相关功能被测过。

13. 覆盖率：统计发生过什么，不替代正确性检查

代码覆盖关心代码结构是否执行；功能覆盖关心需求场景是否观察到。测到一次非法时序，说明负例被激发，不表示DUT正确拒绝了它。

// 教学片段：显式sample参数，避免对可变全局状态的采样竞争
covergroup timing_cg with function sample(int gap, bit bank_id);
  cp_gap: coverpoint gap {
    bins too_short = {[0:2]};
    bins edge_ok = {3};
    bins later_ok = {[4:8]};
  }
  cp_bank: coverpoint bank_id;
  gap_x_bank: cross cp_gap,cp_bank;
endgroup

上例门限3是教学值；实际时序还可能是 max(nCK要求,绝对时间要求)，涉及单位、舍入和频率变化，不能直接搬到LPDDR6。iff决定本次是否采样，不删除不可能达到的bin；不可能场景需重新建模或合理设置 ignore_bins。illegal_bins是覆盖模型诊断的一部分，不代替完整协议checker。

默认cross可能产生大量组合；先问每个组合对应什么需求、是否可达，再决定是否覆盖。覆盖100%只相对于当前模型，遗漏的需求根本不会出现在分母中。

实验04：按bank保存ACT时间

源码 labs/04_coverage/tb.sv 接收教学枚举命令，每个时钟一条；不包括真实CA编码。bank0 ACT后3拍RD、bank1 ACT后4拍RD；分别命中boundary与above。若只保存“最近一次全局ACT”，bank0就会算错。

计数是可移植的过程式覆盖演示，不是仿真器covergroup数据库。正常结果 below=0,boundary=1,above=1。加 +NEGATIVE发送2拍间隔RD，命中below并由独立的失败判定报错；脚本确认非零退出。

动手： 加入bank0 PRE后RD、复位后RD、重复ACT、新旧ACT间隔选择的测试；写清哪些是合法场景。为每个新增规则设计一个会失败的例子。把过程式统计换为商业仿真器的显式sample covergroup时，保留checker。

14. 从实验走进真实CoverageModel

先读 参考项目精读，定位公共类型，再追一条命令从物理采样到coverage的全过程。不要从六万行interface第一行逐句背诵，也不要把生成代码视为规范权威。

再读 独立实现CoverageModel。最终作品应能回答：需求来自哪里；输入是什么；事件什么时候完整；同bank和不同bank如何区分；时间单位是什么；非法输入怎么处理；状态如何复位；如何证明漏采样/重复采样不会被掩盖。

独立实现不要求一次复制整个LPDDR6模型。先关掉参考答案，对一个小需求写出数据类型、纯解码函数、状态模型、checker和测试；再对照参考实现解释差别。接着扩展边沿采样、命令拼接、MR和多bank场景。若手写小模型都无法验证正确，提前写生成器只会扩大错误。

15. 转入UVM之前的自测

无需打分或按时间达标，只检查能否独立完成：

  • 看一段非阻塞赋值，能画出两拍波形。
  • 写一个task驱动请求，准确说明采样边沿。
  • 实现不读取DUT内部结果的参考模型。
  • 主动注入一个数据错误和一个时序错误，验证checker报错。
  • 解释struct值复制与class句柄赋值。
  • 说明约束失败、断言真空通过和覆盖率分母遗漏的区别。
  • 按“需求→刺激→观察→检查→覆盖→复现”讲清自己的小实验。

随后读 UVM教程，把同样的职责移到标准类框架。面试时清楚区分工作经历与个人学习工程，不把本教程实验说成量产UVM项目。
