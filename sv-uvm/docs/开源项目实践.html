开源项目：固定版本后再读和运行

项目文档快照 · 2026-10-21 · 查看原文 ↗

2026-10-09更新： Verilator 5.052正式声明支持UVM 2020-3.2，官方跟踪页也列出2017.1.0/2020.3.1支持及已知限制。下文记录的本机5.032未运行状态仍属实；现在可优先评估独立安装5.052的开源路线，或使用在线/DSim个人免费许可。详见 免费环境选型。本次没有安装新工具。

1. 当前已经下载的项目

Antmicro verilator-uvm-example 已下载到 external/antmicro-verilator-uvm-example，固定提交：

e2c9b49ab9a99298190dd1fb580bd59e2c0a7dd8

其上游保留 Apache-2.0 许可证文件。外部代码没有混入自己的原创实验，不提交vendor副本；复现命令见 scripts/fetch_external.sh。本次只下载与阅读，未在本机编译或运行该UVM工程。

先读 README.md 和 tb.sv：看顶层如何创建interface、配置virtual interface、启动UVM；接着读 sig_pkg.sv 看include顺序，再按sequence、driver、monitor、scoreboard、agent、env、test追踪。实际文件名以目录为准，不假设它一定用 item 而不是 seq_item。

为每个类写四句笔记：输入从哪里来、输出送到哪里、在哪个phase运行、哪里能产生失败。然后和本工作区 labs/03_uvm 对比：哪些是同一职责、哪些只与它的DUT相关。

2. 为什么不直接用当前Verilator运行

上游README建议构建较新的Verilator，并下载 Accellera UVM 2020.3.1。当前WSL实测只有Verilator 5.032，且尚无make。未因此自动升级系统工具或安装商用工具。工具支持会变化，不能凭“安装了Verilator”推断完整UVM可用。上游说明

若将来选择开源UVM路线：先满足上游构建依赖，记录Verilator和UVM的准确版本、固定commit，再跑原例程；确认原例程通过后才加自己的内容。编译通一个例程不等于完整参考CoverageModel也兼容。

下面是待验证的构建入口，前提是已安装适用Verilator及UVM源码；用引号处理本目录的空格与 &。UVM_HOME 必须指向含 uvm_pkg.sv 的src目录：

cd '/mnt/d/cxy/SV&UVM Learning/external/antmicro-verilator-uvm-example'
export UVM_HOME='/实际安装位置/1800.2-2020.3.1/src'
verilator --version
verilator -Wno-fatal --binary --timing -j 2 --top-module tbench_top \
  "+incdir+$UVM_HOME" +define+UVM_NO_DPI "+incdir+$PWD" \
  "$UVM_HOME/uvm_pkg.sv" "$PWD/sig_pkg.sv" "$PWD/tb.sv"
./obj_dir/Vtbench_top +UVM_TESTNAME=sig_model_test

本机当前版本不保证支持此命令。若构建系统对含空格的路径处理失败，把外部工程单独放到WSL的无空格路径，例如 ~/sv_uvm_external/antmicro-example。保存错误后先判断是依赖、路径还是语言支持问题，不要大量改源码绕过检查。

3. 商业仿真器路线

你表示之后会解决商用仿真器。届时先提供产品名、版本、系统与UVM库来源，再针对实际工具调整脚本。目前原创UVM实验给了Questa入口，但没有license、编译或仿真验证记录；不能称为已经跑通。

完成后至少保存：正常用例的9次读检查、9次写观察、0条UVM错误；故障注入用例的预期mismatch；VCD/WLF；运行命令与seed。还要测试watchdog和缺少virtual interface时能明确失败。

4. 其他项目如何选

基础SV练习可看 SystemVerilog Homework；复杂环境阅读可看 Ibex DV。它们的支持范围及入口见 资源调研。不要同时搭建所有工程；先选择能支持当前学习目标的一套。

现阶段基础SV动手的确定入口是本仓库已实际运行的实验01/02/04；开源UVM提供另一套可对照的真实组织方式。Python的pyuvm虽能帮助理解方法学，但不等同于SystemVerilog UVM经历。
